## 0.3.2 深色原生文字与绘制隔离

候选 DLL SHA-256：`70951688e3e010e5f6712607e9905482670ec217c193671c83cea6db1ca9b3b2`。

用户图片表现为原生文件名黑字/灰字的差异，波形和背景颜色基本一致。代码检查确认有兼容风险：旧路径强制子项通知、跳过自有单元格默认绘制，且未完整保存 DC；这些会改变原生主题处理的通知阶段与共享绘制环境。仅凭图片不能确定是唯一原因。

修正为保留原生通知订阅规则，仅给扩展自身请求行后绘制；不将原生未请求的行后绘制回调再送给原生处理器；波形只在原生行结束后覆盖本列。SaveDC/RestoreDC 和裁剪隔离覆盖正常返回及 C++ 异常路径。新页异步数据首次发布时重新刷新原生行一次，避免仅波形列更新后留下初始文字状态。

- `tests/dc-selftest.cpp` 验证文字/背景色、背景模式、当前位置、裁剪区域均恢复。
- `tests/dark-colors.lua`：先设置深色列表，连续 24 次清空内存缓存并切换三个目录，不点击文件、不播放、不在最后重设颜色；原生文字颜色属性保持浅灰，最终实际截图人工检查文字为浅灰。
- 首帧整页、基础波形、布局与原生列重建回归通过。
- 本轮 2018 端口被用户 K 盘实例占用；握手目录检查拒绝了错误目标，没有执行命令。独立测试接收器临时改为 2218/2219，结束后恢复原文件。

测试模拟了深色控件配色，未完整复现用户原主题、其他扩展及所有偶发时序；因此交付为针对绘制兼容风险的修复，不能声称已证明用户截图异常的唯一根因。

## 故障与修复

- 首次峰值缓存构建可能暂时返回 0 点：增加间隔 500ms、最多 5 次的空读重试，冷缓存测试通过。
- 测试目录传给 OpenMediaExplorer 时会定位到父目录：测试改为传入具体音频文件。
- 数据库准备脚本将 Lua `gsub` 的两个返回值传给 JS API，触发参数错误；改为离线注册专用测试库，重启接收器后通过。
- 冷缓存测试中 Lua `%d` 接收非整数：对时间戳取整后重跑通过。

最初一次在沙箱账户下启动的测试 REAPER 未能连接桥接；后续全部功能断言均在正常用户下启动并通过资源目录握手的独立实例执行。
